# Creator Operations · 达播管理中台

**クリエイターへの連絡、提携の進捗、チームの連携を、一つの EC 業務ワークスペースに。**

作者：xiaoyu312 · [FateClear — 生年月日から命式の作成・解説を無料で利用できるサイト](https://fateclear.com) · [X — 作者のプロジェクトと更新情報](https://x.com/liu_xiaoyu27334)

EC の提携営業、クリエイター運用担当者、チーム責任者に向けたワークスペースです。連絡、フォロー、サンプル発送、提携、日程管理、売上の帰属判定、チーム連携を一つの流れで扱います。このソースパッケージには、元の React ワークスペース、ドメインサービスと API、決定的なローカルデモ、単独でも使える Manifest V3 拡張機能 Creator Assistant が含まれます。

**標準の起動方法は、再起動するとリセットされるローカルの合成データデモです。** 実際のワークブック、連絡先、注文、アカウント、秘密情報、非公開素材は含みません。外部プラットフォーム用アダプターのソースは任意の連携用に残していますが、企業向け本番環境として検証済みの構成ではありません。

## まず合成データの例を見る

リポジトリのコピーと Node.js 24 以降を用意し、リポジトリのルートで次の独立したサンプルを実行できます。この例にはアプリの依存パッケージのインストールは不要です。

```sh
npm run demo:assistant
```

[サンプルのソース](examples/assistant-demo.mjs)は、架空のクリエイターを 2 人作成し、未送信の招待文案を 2 件生成します。以下はソースとアサーションから確認できる想定出力です。今回のドキュメント整理ではコマンドを実行していません。

```json
{
  "mode": "synthetic-only",
  "creators": 2,
  "unsentDrafts": 2,
  "network": "none",
  "browser": "not opened",
  "persisted": false
}
```

この例はブラウザーを開かず、ネットワークにアクセスせず、記録を永続化せず、招待も送信しません。単独で使える Creator Assistant の文案作成フローを示すものです。主アプリにも[合成データを使う API サンプル](examples/demo.ts)と[固定シードの生成スクリプト](examples/generate-demo.ts)があります。アプリ全体のセットアップ手順と検証範囲は以下のとおりです。

## ワークスペースを起動する

Node.js 24 以降が必要です。依存パッケージをインストールして起動します。

```sh
npm install
npm run dev
```

`http://127.0.0.1:5173` を開きます。フロントエンドはローカルの `127.0.0.1:4310` にある API へプロキシ接続します。画面でデモ用の役割を切り替えると、権限、クリエイターのフォロー、サンプル発送、提携、日程、チーム、商品を確認できます。元の業務コマンド、CSV インポートのプレビューと確定、エクスポート、監査ルールを保持しています。初期レコードは固定の合成データで、注文は空です。利用者が明示的にインポートしたデータは、そのプロセスのメモリー内にだけ保存されます。

`.env` は必須ではありません。ローカル API のポートを変える場合は、ルートの `.env.example` を参考に自分の `.env` を作り、`DABO_DEMO_API_PORT` を設定します。`npm run dev` と `npm start` はこのファイルを明示的に読み込みます。実際の環境設定をコミットしないでください。

ビルド後にローカルでプレビューする場合：

```sh
npm run build:client
npm start
```

デモはループバックアドレスにのみバインドし、本番モードやプラットフォーム実行モードを拒否します。ローカルセッション Cookie、CSRF 検証、リクエストサイズの制限を使用します。永続化は提供せず、公開サーバーへのデプロイ用エントリーポイントではありません。

| ディレクトリ | 内容 |

| `client/` | 元の React ワークスペース、各画面、操作モデル、チャート、UI コンポーネント、スタイル |

| `server/modules/`、`server/storage/`、`server/invitations/`、`server/platform/` | API、および任意の Nest・データベース・認証・メンバー招待アダプター |
| `extensions/creator-assistant/` | 単独で使える拡張機能の完全なソースとモックテスト |
| `tests/`、`server/tests/` | ドメイン、クライアントモデル、API、役割ごとの権限境界、フロントエンド／バックエンド間の契約を確認するプロセス内テスト |

## Creator Assistant

[简体中文](extensions/creator-assistant/README.md) · [English](extensions/creator-assistant/README.en.md) · [日本語](extensions/creator-assistant/README.ja.md)

```sh
npm run build:assistant
npm run test:assistant
```

ビルドでは自作の `adapters.js` と `page-hook.js` を結合し、`capture-main.js` を生成するだけです。Chrome／Edge の専用テストプロファイルで拡張機能のディレクトリを手動で読み込みます。主アプリのバックエンドは不要で、初回の保存領域は空です。

利用者にアクセス権のある Douyin（抖音）、Weixin Channels（视频号）、Xiaohongshu（小紅書）、Kuaishou（快手）のページから、クリエイター情報とフォロー状況をローカルに記録します。Douyin／Weixin の招待フローは利用者が明示的に開始した後、現在のプラットフォームセッションを使用して実際のプラットフォームと通信します。そのため、拡張機能全体をオフラインアプリとは説明できません。権限、失敗時の対応、データの保管については拡張機能のドキュメントを参照してください。

## 任意のプラットフォーム連携

標準のワークスペースは実際のプラットフォームプロフィールを読み込まず、本番用のメンバー招待も有効にしません。元のブランド、ワークブック、メンバー画面は条件付きの分岐として残しています。`VITE_ENABLE_PLATFORM_INTEGRATIONS` の既定値は `false` で、ドキュメント URL とプロフィール SDK の URL は空です。ブラウザーから見える `VITE_*` 設定に秘密情報を入れないでください。

実際に連携するには、信頼できる認証・CSRF ミドルウェア、組織／アプリケーション ID、サーバー側の役割マッピング、CSV プレビュー署名用の秘密情報、ワークブック認証情報とブランド registry、確認済みのデータベース schema／RPC マイグレーション、プラットフォームの役割管理 SDK が必要です。任意のモジュールは、自分の本番エントリーポイントで構成し、必要な設定を注入してください。**完全な企業向け AppModule、ワークブック永続化サービス、データベースマイグレーションは含まれていません。** フラグを有効にするだけでは本番連携は完成しません。ブラウザーから渡された ID を、検証済みのサーバー側コンテキストの代わりにしてはいけません。[バックエンドの範囲説明（中国語）](server/README.md)を参照してください。

`@lark-apaas/client-toolkit@1.2.74` は、保持しているプラットフォーム画面のビルドに使います。このバージョンが公式の公開 npm registry に存在することは以前の準備段階で確認されています。標準のローカル画面は、この SDK の実際のプラットフォーム処理を開始しません。任意のサーバー依存パッケージは optional peer として宣言しています。SDK はそれぞれの条件に従うもので、実装の同梱やライセンスの変更は行っていません。

## 検証と既知の不足

```sh
npm test
npm run test:assistant
npm run typecheck
npm run demo
npm run demo:assistant
npm run generate:demo
```

ソース準備段階の過去の記録では、外向きネットワークとポート待ち受けを禁止したローカル環境で、主アプリの **154 件**、拡張機能の **164 件**のテストが成功しています。実際の Vite 設定でフロントエンドをビルドし、フロントエンドとバックエンドの型チェックも通過しています。当時は元のプロジェクトにインストール済みの依存パッケージを読み取り専用で参照し、新規インストール、ブラウザーの起動、実サービスの起動は行っていません。今回の多言語ドキュメント整理では静的チェックのみを行い、これらのテスト、ビルド、型チェックは再実行していません。

- クリーンな環境での `npm install` は未検証で、新しいロックファイルも含みません。直接依存のバージョンは固定していますが、間接依存は変わる可能性があります。
- フロントエンドには大きな chunk が残っています。ブラウザー操作、見た目、性能、Windows 実機での検証は未実施です。
- 実際のログイン、プラットフォーム上のプロフィール検索、招待の到達、データベースマイグレーション／RPC、本番デプロイは未検証です。
- 一部の異常系テストには、フィルタリング、精度、拒否処理を確認するための明らかに架空のトークン、電話番号文字列、長い整数が含まれます。実行用の認証情報ではありません。
- 実行後のインポートデータ、エクスポートファイル、ブラウザー保存領域、バックアップは利用者が管理し、ソースリポジトリに含めないでください。
